# Whisperlane v0.8.3

Whisperlane v0.8.3 replaces the fragile engine package with two self-contained
runtimes, makes upgrades safe, and turns a failed engine start into a sentence
that names the cause.

## No Visual C++ redistributable dependency

- The transcription engine ships as two single executables:
  `whisper-server.exe` for Vulkan and `whisper-server-cpu.exe` for the
  processor.
- Both are built with `BUILD_SHARED_LIBS=OFF` and the static MSVC runtime, so
  there is no `vcruntime140`/`msvcp140` dependency and no separate
  `whisper`/`ggml` DLL set.
- `vcomp140.dll` travels beside them because OpenMP is the faster processor
  path; it imports only `KERNEL32.dll`, so no CRT boundary crosses the package.
- A Vulkan start that exits or times out falls back to the processor build once
  in the same run.

## Upgrades are versioned and survive a failed install

- Runtimes install under
  `%APPDATA%\com.whisperlane.desktop\runtime\<pin>\`.
- `runtime\current` is a plain text pointer written through a temporary file and
  an atomic rename. No symlink, no elevation, no Developer Mode.
- The new version is staged before the pointer moves. The previous version
  stays until the next install, so an interrupted upgrade leaves a working
  engine.
- The old flat runtime is migrated and cleaned up. Unrelated files and folders
  are left alone, and a removal the OS refuses is logged instead of swallowed.

## A failed start now says what happened

- Engine stderr goes to
  `%APPDATA%\com.whisperlane.desktop\logs\engine.log` with a header per launch.
- The interface shows one mapped sentence: missing DLL, damaged engine files,
  no compatible graphics device, not enough graphics memory, an unloadable
  model, or a timeout. Raw stderr never reaches the pill.
- A child that exits early fails immediately instead of waiting out the
  90-second timeout.
- The eager startup probe is gone. The first real take launches the engine, and
  the banner from that launch is the backend verification.
- Quitting stops the engine this process started. It no longer leaves a server
  running with the model loaded, and it never touches a server it did not start.

## Models are checked, not guessed

- Presence is exact byte length, not "the path exists".
- A verified download records its length in a `.size` sidecar beside the model;
  a truncated file is reported as incomplete instead of being handed to the
  engine.
- Redownloading an incomplete model repairs it. "Not downloaded" and
  "incomplete" are separate answers on the pill, the tray, and the model row.

## Packaging and verification

- Installers: NSIS setup and MSI for Windows 10/11 x64.
- Verify the download against `SHA256SUMS.txt`:

  ```powershell
  Get-FileHash Whisperlane_0.8.3_x64-setup.exe -Algorithm SHA256
  ```

- The installer itself is not Authenticode-signed, so Windows SmartScreen may
  ask for confirmation. The updater artifact is signed and verified by the app.
