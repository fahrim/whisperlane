# Whisperlane v0.8.4

Whisperlane v0.8.4 is a hotfix for an upgrade crash introduced in 0.8.3.

## What went wrong

Upgrading an existing 0.8.1/0.8.2 install left the old DLL set
(`ggml*.dll`, `whisper.dll`, `whisper-cli.exe`) in the installed `runtime`
folder. 0.8.3 copies the runtime into a versioned data directory, and that
copy carried the old files with it. The new static engine then found a second
`ggml` beside itself and stopped on the first take with:

```
GGML_ASSERT(prev != ggml_uncaught_exception) failed
0xC0000409
```

## The fix

- The runtime installer copies only the three files the package ships:
  `whisper-server.exe`, `whisper-server-cpu.exe`, and `vcomp140.dll`.
- An existing version directory is cleaned of `ggml*.dll`, `whisper.dll`,
  `whisper-cli.exe`, and `.pin` on the next start.
- The NSIS installer removes the obsolete set from the install tree, so an
  upgrade does not leave it behind again.
- Tests cover both the copy filter and the in-place cleanup.

## If you are on 0.8.3

Update to 0.8.4. If you cannot update yet, delete these files from
`%APPDATA%\com.whisperlane.desktop\runtime\engine-vulkan-b5454-static\`:

```
ggml-base.dll
ggml-cpu.dll
ggml-vulkan.dll
ggml.dll
whisper.dll
whisper-cli.exe
.pin
```

Keep `whisper-server.exe`, `whisper-server-cpu.exe`, and `vcomp140.dll`.

## Everything from 0.8.3

- Two self-contained engine executables, Vulkan and processor, with the
  static MSVC runtime and an app-local `vcomp140.dll`. No Visual C++
  redistributable dependency.
- Versioned runtime directories with an atomic `current` pointer, staged
  upgrades, and cleanup that leaves unrelated files alone.
- Engine stderr in a log, mapped failure sentences, early-exit detection,
  a 90-second timeout, and one processor fallback per run.
- The first real take verifies the backend from the engine banner; there is
  no eager startup probe.
- Exact-byte model presence with a `.size` sidecar; incomplete models are
  named and repaired by redownloading.
- Quitting stops the engine this process started.

## Packaging and verification

- Installers: NSIS setup and MSI for Windows 10/11 x64.
- Verify the download against `SHA256SUMS.txt`:

  ```powershell
  Get-FileHash Whisperlane_0.8.4_x64-setup.exe -Algorithm SHA256
  ```

- The installer itself is not Authenticode-signed, so Windows SmartScreen may
  ask for confirmation. The updater artifact is signed and verified by the app.
